# dev-flow：八步研发编排

对用户给出的 PRD 路径、当前目录中的 PRD，或对话需求执行以下流程。默认使用中文输出；除非用户要求 `--overview`，不要改动 `总览.md`。

## 参数与恢复

支持 `--skip N,M`、`--from N`、`--only N`、`--resume`、`--overview`。显式的 `--from` 或 `--only` 覆盖恢复状态；`--skip` 与恢复状态叠加。每个步骤完成后更新会话目录的 `.dev-flow-state.json`，流程完成后删除它。

## 执行顺序

1. 读取 `read-prd` 技能，扫描并总结 PRD；先请用户确认。
2. 未指定显式流程参数时，依据需求是否纯文档、是否含歧义/跨模块/依赖，推荐文档、快速或标准路径并请用户确认。
3. 标准或文档路径读取 `grill`；一次只问一个问题，先给推荐答案。
4. 标准或文档路径读取 `qa-record`，写入 `问答记录.md`。
5. 读取 `tech-plan`，为每项任务写行为化计划并请用户确认。
6. 非文档路径读取 `implement`，按垂直切片推进并在每个切片后验证。
7. 非文档路径读取 `self-test`，根据验收标准检查行为与测试质量。
8. 非文档路径读取 `code-review`，先运行可用测试，再逐文件审查；有必须修复项时回到实现。
9. 读取 `summary`，写入交付总结并完成可选的 `--overview` 更新。

使用本插件同目录下对应技能的完整方法、输出格式和边界规则；不要简化或跳过用户确认节点。
